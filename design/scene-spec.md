# 词遇岛 · 第一版场景制作说明

## 创作目标与范围

这是文字创作任务。保留用户确定的关系：固定的小屋、可复用的外出冒险、七次学习累计线索、伙伴找到后入住小屋；玩法不因换教材而清空成长。

本轮制作一个开放式小屋、一个林间营地、一个探险主角和第一个伙伴。美术为暖色、圆润、有厚度的微缩玩具世界，使用真实三维几何、标准材质和实时光照。角色为原创造型，未复用其他角色身份，也未使用网络角色模型或教材插图。

身份与设计空间：

| 资产 | 保留项 | 本轮主动设计 |
| --- | --- | --- |
| 芽芽 | 持续陪伴孩子冒险的主角 | 橘色小狐狸、绿色围巾、绿色背包、奶油色口鼻、弯曲白尾尖 |
| 团团 | 首个收集后入住的伙伴 | 奶白圆兔、长耳、粉色内耳、绿色小领巾 |
| 小屋 | 固定场景，家具承担产品入口 | 左后两面墙、开放正面和右侧、木地板、床、书架、线索板、伙伴坐垫 |
| 营地 | 可复用冒险场景，学习任务依附真实物件 | 草地岛、树、帐篷、石路、池塘与小桥、食物箱、告示牌、邮筒和宝箱 |

小屋、角色身份、具体造型与相对尺寸均为本轮设计假设，等待孩子试用意见。布局不宣称来自实测。

## 空间与取景

Blender 使用 Z-up，角色正面 -Y；导出 glTF 后 Y-up，角色正面 +Z。本文以下坐标均为 **glTF / Three.js**，地面 `y=0`。

| 场景 | 推荐相机 position | 推荐 target | 角色建议位置 |
| --- | --- | --- | --- |
| 小屋 | `[9,8,11]` | `[0,1,0]` | 芽芽 `[-0.5,0,1.25]`；团团 `[2.6,0.31,1.3]` |
| 营地 | `[8,8,10]` | `[0,0.5,0]` | 芽芽 `[-0.4,0.06,1.3]`；团团揭晓位置 `[-1.6,0.06,2.2]` |

小屋占地约 `10×7`，墙在后侧 `z=-3.35` 与左侧 `x=-4.94`，正面与右侧有意开放；营地半径约 `4.6`。推荐正交斜俯视，手机纵屏可适当转向和拉远；不能以简单裁切使伙伴或交互物件离开画面。

角色独立导出、脚底为原点。芽芽高度约 2.05、团团含长耳约 2.05，应用内建议 scale 约 `.85`、`.8`。具体以导出资产边界为准。

## 物件事件约定

交互对象通过 GLB 节点 extras 的 `interactionId` 标识。加载后需要向父级追溯语义，使用真实三维拾取，并区分点击、镜头拖动和双指操作。下表为物件中心附近的辅助定位，不能代替拾取。

| interactionId | 真实物件 | 中心附近 | 应用行为 |
| --- | --- | --- | --- |
| `home.door` | 小屋门、门框、把手 | `[2.85,1.28,-3.25]` | 出发冒险 |
| `home.bookshelf` | 书架与书籍 | `[-3.65,1.25,-2.05]` | 打开教材书架 |
| `home.clues` | 墙上七格线索板 | `[0.85,2.22,-3.0]` | 查看累计线索 |
| `home.bunny` | 伙伴坐垫与入住位置 | `[2.6,0.27,1.3]` | 查看伙伴；模型本身由应用另行挂载 |
| `camp.crate` | 木箱、牛奶盒、米饭、鸡腿 | `[-2.5,0.7,0.9]` | 听辨任务 |
| `camp.sign` | 告示牌和字母格 | `[0.4,1.23,-0.8]` | 拼写任务 |
| `camp.mailbox` | 邮筒 | `[2.8,1.13,-0.2]` | 示范音与录音回听 |
| `camp.chest` | 宝箱 | `[1.6,0.5,1.8]` | 学习完成后领取今日线索 |

`ChestLid` 为真实铰链子节点，extras `motionRole='lid'`，轴为 X；起始关闭，应用可从当前进度向负 X 旋转打开。盖子上的金属带属于盖子，锁与箱体保持固定。状态应从“待完成”进入“可领取”后才授予奖励；快速复点不重复发奖。

## 角色与动作

角色躯干、头脸使用融合体积及平滑重网格，保留连贯的体积轮廓。口鼻、耳内、围巾和背包是有厚度或贴合宿主的独立部件。狐狸尾巴使用变化截面的连续曲面，兔子长耳是有厚度的曲面。

所有头部配件、眼睛、口鼻和耳朵随同一头部节点联动：

- 芽芽：`HeroBody` (`role=body`)、`HeroHead` (`role=head`)、`HeroTail` (`role=tail`)、`HeroEarLeft` / `HeroEarRight` (`role=ear`)。
- 团团：`BunnyBody`、`BunnyHead`、`BunnyEarLeft` / `BunnyEarRight`，使用对应 `role`。

角色附带约 4 秒 idle 动画片段，表现很轻的胸部呼吸、转头和耳朵摆动，脚部保持地面接触。应用可以播放 GLB 片段；同一变换通道不应同时被片段和网页动画写入。庆祝若使用外层 wrapper，须保持落地和最终归位。

本轮未制作自由行走、自然步态、口型、战斗或自动寻路；不将静态模型平移称为已完成行走。GLB 本身不包含题目、奖励、存档、点击事件或网页灯光逻辑。

## 制作与复建

已确认可执行工具为 Blender **4.5.15 LTS**：

```sh
/Users/gongshenshen/Documents/ChatGPT/3DSence/.tools/Blender.app/Contents/MacOS/Blender \
  --background --python tools/build_world.py -- --output assets/models
```

可用 `--asset home`、`--asset camp`、`--asset hero`、`--asset bunny` 单独重建，`--render` 额外输出内部 Blender 参考图。正常输出为四份 `.glb`、四份压缩 `.blend` 母版和资产统计。

所有颜色使用标准 Principled BSDF；无程序化专属材质、外部贴图或网络加载。静态场景按材质与交互身份合批，避免大量小花、木板形成独立绘制对象。网页重新建立灯光与阴影，不能假设 Blender 预览与最终 WebGL 像素完全一致。

macOS 受限进程可能在 Python 执行前的 Metal 检测崩溃。本轮曾观察到此情况，需要已授权的正常本机图形权限运行相同生成命令；不需要安装另一个 Blender。

## 验收边界

资产结构验证检查 GLB 是否可读、语义节点是否存在、动画片段与真实节点是否有关联、包体与边界是否合理。产品中的 Three.js 实际画面仍需检查整体、角色近看、侧背、动作过渡和物件拾取；桌面窄屏模拟不等于 iPhone / iPad 真机性能验收。

实际验证结果记录在 `design/asset-verification.md`。最终产品不显示灰模、内部诊断或制作控制面板。
