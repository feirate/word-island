# 词遇岛：0.6 版边界与后续路线

## 产品目标

服务三年级孩子，每天约 15 分钟，以听懂、拼写、会说为学习目标。同一浏览器最多保存 3 个本地用户，个人进度独立。先让孩子能独立完成一轮，并愿意在后续日期回来，再判断是否要扩充大地图、伙伴互动或战斗规则。

持续使用看实际日期：最近 7 / 14 天学习过几天、安排任务完成几次，以及是否在新鲜感过去后继续回来。单个孩子的本地记录只是个人观察，不把演示操作、挂机时长或宠物点击次数当成学习效果。

## 首版形成闭环

- 每次访问或刷新先选择名字，不自动进入上一次的用户。名字只用中文汉字和英文字母，可混用，1–12 个字，英文大小写不区分重名；首尾空白去除、全角字母规范化，内部空格、数字、标点和表情不接受。用户无需密码、登录或云端账号。
- 固定小屋承担出发、回家、查看线索与伙伴入住。
- 复用一处冒险营地，通过任务内容与少量布置变化承接学习，不为每个单词单独制作新地图。
- 小朋友主角、狐狸向导芽芽和动物伙伴具有真实三维体积。小朋友是当前用户的小岛分身，显示该用户的名字；芽芽负责故事和带路，与狐狸伙伴橙橙保持独立身份。需要动作时使用模型片段或明确的程序动画，手机轻点承担主要互动。
- 听辨、拼写输入和录音回放构成最小学习循环。约 5 个新词是初始负荷参考，不要求每天必须新增 5 个；需要复习时优先复习。
- 正式存档每累计 7 个不同本地日期的学习线索，按顺序邀请一位伙伴入住；八位伙伴对应最多 56 个奖励日期。断签不清零，当天重复学习不重复奖励日期线索，集齐以后仍记录每日完成。
- 伙伴图鉴从一开始展示八位角色：团团兔、栗栗松鼠、米米猫、豆豆狗、刺刺刺猬、慢慢乌龟、圈圈浣熊、橙橙狐狸。卡片缩略图来自实际三维截图，选中后在一个共用画布里旋转查看同一套 GLB；未获得显示灰色，获得后恢复原色并留在小屋固定位置，点角色有各自的气泡对白。
- 演示存档独立，可预览团团入住，家长入口也可预览全部八位伙伴入住，退出后回到真实学习进度。
- 每位用户首次由芽芽通过人物气泡介绍“读懂林间英语消息，寻找朋友”的故事，并按真实任务完成情况带领孩子出门、听辨、拼写、跟读、开宝箱和回家；可跳过、重看，结束后仍能点角色问路。引导设置归属该用户，独立于学习进度备份，不修改奖励或假装完成练习。
- 个人学习进度、伙伴、跟读完成状态、故事引导、录音及本机恢复备份彼此隔离。JSON 手动导入导出只针对当前用户的学习进度，不包含用户列表、引导、录音或教材音频。
- 用户可新建、选择或删除名字；删除必须再次确认，清理该用户在当前浏览器的个人记录、录音与本机备份，其他用户和共用教材音频保留。外部已导出的文件由用户管理。
- v1/v2 学习存档先按旧规则校验，再迁移为 v3；保留已有线索、伙伴和学习记录。被旧七条线索上限截掉的已完成历史日期不补发奖励，新的完成日期继续下一轮。旧未命名浏览器存档在首次起名字时完整接续，包含引导、备份和录音，只迁给第一个用户；只有录音也可接续。迁移失败保留原数据，不创建半完成用户。外层备份格式兼容，导入源文件不修改。

## 教材与语音边界

当前接入所提供 KB3 扫描学生用书的 Hello! 与 8 个主单元核心词，并保留 KB2 Unit 6。目录与正文已对照扫描件，具体版次因未见版权页仍不确定；来源与页码见 kb3-source-notes.md。核心词练习不是整本课文与练习的复刻。

拼读练习从本课实际字母组合和词例出发，例如正确标注 `ch` 在 `chicken` 等词中的发音；不要把所有拼写相近词都说成同一发音，也不为所有单词强行编造词根。

当前内置所接入核心词与短句的 Daniel 英音合成示范，明确标注“合成音，非教材原音”，并作为静态资源缓存，不要求孩子设备安装声线。家长入口已支持按文件名导入自己的本地音频，优先用于相应词条或句子；这些是当前浏览器的共用教材资源，删除个人用户时保留。实际教材原音仍需用户提供配套文件。

浏览器录音和回放留在设备上。自动转写的离线支持及儿童短词识别质量需先做实机验证；发音纠错、音素评分、云端语音服务均不在本轮范围内。

## 三维实现的控制范围

采用 Blender 可编辑资产 → GLB → 本地 Three.js。保留固定小屋、营地、主角与伙伴的稳定身份和尺度，通过复用网格、材质、场景与动作控制资源量。

0.6 使用 ub-mode 控制兼容迁移与改动边界，使用 scene-to-three 的本地建模和多角度检查流程；复用已有 Blender、Three.js 和浏览器检查工具，不增加安装步骤或云端建模服务。新增小朋友主角并保留芽芽向导；八位伙伴在图鉴和小屋共享模型，图鉴只用一个预览画布，未获得的灰色状态由材质表达，不另造一套模型。

简单呼吸、点头、转身和庆祝优先；复杂步态、坐站及角色交互需要相应绑定和多角度验证。传送/场景切换可以作为正式导航方式，但不能把坐姿模型平移宣称为完成行走动画。

手机滚动到题目时，离开视口的三维画布暂停动画、阴影与渲染，返回后恢复。手机验收分别关注轻点与拖动区分、点击目标大小、输入键盘遮挡、录音权限、屏幕旋转、WebGL 性能，以及从后台恢复。桌面缩小窗口不等于手机实机通过。

## 后续迭代顺序

1. **真实使用反馈**：观察一周左右的回访日期、任务完成和孩子卡住的位置，先减少阻力。
2. **内容与原音**：在已接入 KB3 核心词基础上结合课堂进度审校和扩充；在现有文件名映射基础上完善音频导入提示、音频包备份与纠错。
3. **按表现安排**：已按单元安排新词、跨单元复习，听辨与拼写分开记录；继续根据真实使用校准难度。不要用“播放过”或“录过音”直接判定掌握。
4. **伙伴体验**：八位伙伴和固定入住位置已接入，先观察孩子喜欢谁、能否理解线索与入住的关系，再完善对白、少量互动和动作；后续角色沿用小屋和营地模板，不先建立复杂养成经济。
5. **学习驱动战斗**：在学习闭环与持续使用稳定后实施。

## 未来战斗模式，本轮不做

计划由听辨、拼写、跟读任务驱动攻击、防御和主角/伙伴的动态反馈。学习决定战斗推进：完成学习任务触发胜利，不靠连续点按或等待动画就能胜利。

设计时需要先明确：题目难度与伤害/防御的关系、错误后重试与提示、跟读无法自动判断时的完成标准、角色动作中断与复位，以及奖励是否会诱导跳过学习。不得为了战斗加入强制付费、排行榜或云端账号。

## 发布与离线

静态 GitHub Pages 负责 HTTPS 程序分发，没有学习数据后端。代码、模型与部署资源可以公开查看；孩子的存档与录音不放入仓库。

核心程序与内置英音精确预缓存，场景、全部伙伴模型及实际三维缩略图按生成清单独立准备。离线准备检查完整资源，不限于已获得伙伴；只在响应成功后写缓存，尚未准备好的资源需给出可理解的反馈。更新缓存版本后重新验收，不能仅凭 Service Worker 已注册就宣称全部资源离线可用。

本轮仍只在本地实现和检查，由用户手动推送到 GitHub。正式发布前，以实际浏览器交互、离线重载、手机尺寸和设备试用结果确认体验；测试脚本覆盖范围与真机验收分别记录。
