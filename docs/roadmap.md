# 词遇岛：首版边界与后续路线

## 产品目标

服务一个三年级孩子，每天约 15 分钟，以听懂、拼写、会说为学习目标。先让孩子能独立完成一轮，并愿意在后续日期回来，再判断是否要扩充大地图、伙伴数量或战斗规则。

持续使用看实际日期：最近 7 / 14 天学习过几天、安排任务完成几次，以及是否在新鲜感过去后继续回来。单个孩子的本地记录只是个人观察，不把演示操作、挂机时长或宠物点击次数当成学习效果。

## 首版形成闭环

- 固定小屋承担出发、回家、查看线索与伙伴入住。
- 复用一处冒险营地，通过任务内容与少量布置变化承接学习，不为每个单词单独制作新地图。
- 主角和动物伙伴具有真实三维体积；需要动作时使用模型片段或明确的程序动画，手机轻点承担主要互动。
- 听辨、拼写输入和录音回放构成最小学习循环。约 5 个新词是初始负荷参考，不要求每天必须新增 5 个；需要复习时优先复习。
- 正式存档按 7 个不同本地日期累计线索，完成后邀请伙伴入住。断签不清零，当天重复学习不重复奖励日期线索。
- 演示存档独立，可快进到 7 格以检查完整过程，退出后不污染真实学习数据。
- 进度在本地保存，支持 JSON 手动导入导出。原始录音不作为普通进度 JSON 的默认内容。

## 教材与语音边界

首批内容取 Kid's Box 2 Unit 6 食物、三餐主题。用户的家庭朗读任务能指示本课范围，但不能替代整册教材的版本核验与词表审校。

拼读练习从本课实际字母组合和词例出发，例如正确标注 `ch` 在 `chicken` 等词中的发音；不要把所有拼写相近词都说成同一发音，也不为所有单词强行编造词根。

首版内置 10 个单词与 3 条短句的 Daniel 英音合成示范，明确标注“合成音，非教材原音”，并作为静态资源缓存，不要求孩子设备安装声线。家长入口已支持按文件名导入自己的本地音频，优先用于相应词条或句子；实际教材原音仍需用户提供配套文件。

浏览器录音和回放留在设备上。自动转写的离线支持及儿童短词识别质量需先做实机验证；发音纠错、音素评分、云端语音服务均不在本轮范围内。

## 三维实现的控制范围

采用 Blender 可编辑资产 → GLB → 本地 Three.js。保留固定小屋、营地、主角与伙伴的稳定身份和尺度，通过复用网格、材质、场景与动作控制资源量。

简单呼吸、点头、转身和庆祝优先；复杂步态、坐站及角色交互需要相应绑定和多角度验证。传送/场景切换可以作为正式导航方式，但不能把坐姿模型平移宣称为完成行走动画。

手机验收分别关注轻点与拖动区分、点击目标大小、输入键盘遮挡、录音权限、屏幕旋转、WebGL 性能，以及从后台恢复。桌面缩小窗口不等于手机实机通过。

## 后续迭代顺序

1. **真实使用反馈**：观察一周左右的回访日期、任务完成和孩子卡住的位置，先减少阻力。
2. **内容与原音**：确认教材版本，补齐当前单元和一册内容；在现有文件名映射基础上完善音频导入提示、音频包备份与纠错。
3. **按表现安排**：将听辨、拼写、会说分开记录，再根据实际错误和复习结果调整下一次任务。不要用“播放过”或“录过音”直接判定掌握。
4. **伙伴扩展**：沿用小屋和营地模板，逐步添加少量性格、造型及动作，不先建立复杂养成经济。
5. **学习驱动战斗**：在学习闭环与持续使用稳定后实施。

## 未来战斗模式，本轮不做

计划由听辨、拼写、跟读任务驱动攻击、防御和主角/伙伴的动态反馈。学习决定战斗推进：完成学习任务触发胜利，不靠连续点按或等待动画就能胜利。

设计时需要先明确：题目难度与伤害/防御的关系、错误后重试与提示、跟读无法自动判断时的完成标准、角色动作中断与复位，以及奖励是否会诱导跳过学习。不得为了战斗加入强制付费、排行榜或云端账号。

## 发布与离线

静态 GitHub Pages 负责 HTTPS 程序分发，没有学习数据后端。代码、模型与部署资源可以公开查看；孩子的存档与录音不放入仓库。

核心程序与内置英音精确预缓存，模型独立准备。只在响应成功后写缓存；离线未准备好的资源需给出可理解的反馈。更新缓存版本后重新验收，不能仅凭 Service Worker 已注册就宣称全部资源离线可用。
